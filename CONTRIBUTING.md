# Contributing to Securebox

Thank you for your interest in contributing to Securebox!

## Development Workflow
1. Create a new branch for your feature or fix.
2. Implement the changes and add corresponding tests.
3. Ensure code follows the project's linting and formatting rules.
4. Submit a Pull Request with a detailed description of the changes.

## Engineering Rules
- Build modular, maintainable components.
- Avoid unnecessary abstractions.
- Never hardcode API keys.
- Never execute untrusted repository code during scanning.
- Never silently skip files without reporting coverage.
- Do not implement placeholder features that appear functional.
- Add tests for every meaningful backend capability.
